# RecomGraph — DSA-3 Recommendation Engine

A database-backed recommendation engine implementing the DSA concepts in the project presentation:

- Hash Map / indexed lookup
- Weighted graph / adjacency-list style relevant subgraph
- Jaccard similarity
- Binary search
- Merge sort
- Min-heap priority queue for Top-K

## Architecture

MovieLens 32M dataset -> MySQL -> Node/Express DSA engine -> React frontend

The project does **not** store a hard-coded movie catalogue in JavaScript.

## 1. Requirements

- Node.js 18+
- MySQL 8+
- VS Code
- Windows PowerShell is fine

## 2. Download MovieLens

From the project root in PowerShell:

```powershell
.\scripts\download-dataset.ps1
```

This downloads MovieLens 32M from GroupLens and extracts it to:

```text
data/ml-32m/
```

The 32M release contains 87,585 movies and 32 million ratings.

## 3. Create MySQL database

From the project root:

```powershell
Get-Content .\database\schema.sql -Raw | mysql -u root -p
```

Enter your MySQL root password.

## 4. Configure backend

```powershell
Copy-Item .\backend\.env.example .\backend\.env
notepad .\backend\.env
```

Set:

```env
DB_HOST=localhost
DB_PORT=3306
DB_NAME=recomgraph
DB_USER=root
DB_PASSWORD=YOUR_MYSQL_PASSWORD
```

## 5. Install backend dependencies

```powershell
cd backend
npm install
```

## 6. Import movie catalogue

```powershell
npm run import:catalog
```

This imports the MovieLens movie catalogue and external IDs into MySQL. It does not put the dataset into source code.

## 7. Import rating statistics

```powershell
npm run import:ratings
```

This streams the 32M ratings file once and stores only per-movie average rating and rating count in `movie_stats`. We intentionally do not store all 32M raw ratings in MySQL for this prototype.

## 8. Start backend

```powershell
npm start
```

Backend:

```text
http://localhost:5000
```

Health check:

```text
http://localhost:5000/api/health
```

## 9. Start frontend

Open a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

Open the Vite URL, normally:

```text
http://localhost:5173
```

## Database tables

- `movies` — MovieLens catalogue
- `movie_stats` — average rating + rating count derived from MovieLens ratings
- `app_users` — users of our prototype
- `user_preferences` — selected genres/tags
- `interactions` — likes, watches and ratings generated by the application
- `movie_tags` — reserved for future tag import

## Recommendation flow

1. Read user profile from MySQL.
2. Build a preference set.
3. Fetch interacted movies.
4. Build a relevant weighted graph using shared genres.
5. Calculate Jaccard similarity.
6. Score candidates.
7. Keep only Top-K candidates with a min-heap.
8. Return ranked recommendations to React.

## Why the graph is dynamic

The first prototype compared every movie with every other movie. That is O(N²) and becomes inappropriate for a large catalogue. The database version constructs only the graph around the user's interacted movies, which demonstrates the graph concept without materializing millions of unnecessary edges.
